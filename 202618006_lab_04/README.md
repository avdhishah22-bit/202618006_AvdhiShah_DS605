# Airbnb NYC Price Prediction — End-to-End ML Project

**Course:** DS605 — Fundamentals of Machine Learning · Lab-4
**Dataset:** Kaggle "New York City Airbnb Open Data" (`AB_NYC_2019.csv`)

All project files live flat in this one folder (no subfolders), as required.

## Files

| File | Purpose |
|---|---|
| `Airbnb_Price_Prediction.ipynb` | Task 1 (EDA, cleaning, feature engineering) + Task 2 (model comparison, tuning, evaluation) + Task 4 (final summary). Saves `airbnb_price_pipeline.pkl` at the end. |
| `app.py` | Task 3 — Streamlit app that loads the saved pipeline and predicts nightly price from user input. |
| `airbnb_price_pipeline.pkl` | Saved scikit-learn pipeline (preprocessing + trained model). **Generated by running the notebook** — see setup below. |
| `AB_NYC_2019.csv` | The dataset (place your downloaded copy here). |
| `requirements.txt` | All dependencies. |

## Setup & How to Run

```bash
pip install -r requirements.txt --break-system-packages   # or use a venv, see note below

# 1. Place AB_NYC_2019.csv in this same folder (download from Kaggle if you haven't already)

# 2. Run the notebook top to bottom — this trains the models, tunes the best one,
#    and saves airbnb_price_pipeline.pkl
jupyter notebook Airbnb_Price_Prediction.ipynb

# 3. Launch the Streamlit app (only works after step 2 has produced the .pkl file)
streamlit run app.py
```

> If `pip install` complains about an "externally managed environment", either add
> `--break-system-packages` to the command, or create a virtual environment first
> (`python -m venv venv`, then activate it) and install inside that instead.

## Project Summary

### Task 1 — Data Analysis & Preparation
- **Cleaning:** removed `price == 0` rows (not real bookable prices), capped the top 1% of
  prices as extreme outliers, and capped `minimum_nights` at 365 (a handful of listings had
  values like 1000+, clearly not realistic short-term-rental minimums).
- **Missing values:** `reviews_per_month` and `last_review` are missing exactly when a
  listing has zero reviews — resolved logically (0 reviews/month; "days since last review"
  set to the dataset maximum, i.e. treated as long-stale) rather than dropped or naively imputed.
- **Feature engineering:** derived `days_since_last_review` from the raw date, and modeled
  `log1p(price)` instead of raw price, since price is heavily right-skewed.
- **Feature selection:** kept borough (`neighbourhood_group`), `room_type`, coordinates, and
  listing/host activity stats (reviews, availability, host's listing count). Dropped
  identifiers (`id`, `host_id`, `name`, `host_name`) and the high-cardinality `neighbourhood`
  column (~220 categories) in favor of the coarser `neighbourhood_group` + coordinates.

### Task 2 — Model Training & Evaluation
- Compared **Linear Regression, Ridge, Random Forest, and HistGradientBoosting** on
  RMSE (log-price scale), R², and MAE (in dollars), and checked the train/test RMSE gap
  as an overfitting signal for each.
- Tuned the best-performing tree ensemble with `RandomizedSearchCV` (5-fold CV) over
  `n_estimators`, `max_depth`, `min_samples_leaf`, and `max_features`.
- Final pipeline (preprocessing + tuned model) is saved as a single object with `joblib`,
  so `app.py` can call `.predict()` directly on raw new input without re-implementing any
  preprocessing.
- **Exact final metrics (RMSE, R², MAE) will differ once you run this on the real
  `AB_NYC_2019.csv`** — they're written directly into the notebook's output cells and
  summarized in the Task 4 markdown cell at the end for you to fill in.

### Task 3 — Streamlit Application
`app.py` takes borough, room type, coordinates, minimum nights, review stats, host listing
count, and availability, and returns a predicted nightly price with a confidence caveat.
It loads `airbnb_price_pipeline.pkl` directly, so the UI stays completely decoupled from
the training code.

### Task 4 — Final Summary & Limitations
Written as the last markdown cell of the notebook, to be completed with your actual run's
numbers. Key limitations already identified: the fine-grained `neighbourhood` feature was
dropped for cardinality reasons (some within-borough variation is lost), the model reflects
2019 market conditions only, and extreme luxury listings (top 1% of price) were excluded
from training so predictions for very high-end listings will be systematically low.

## Deploying the App (optional)
To deploy on Streamlit Community Cloud: push this whole folder to a public GitHub repo
(including the `.pkl` file — it's small enough to commit directly), then point Streamlit
Cloud at `app.py`. Because `app.py` anchors all paths to its own folder location rather
than the working directory, it will work correctly regardless of where in the repo
structure it's deployed from.
